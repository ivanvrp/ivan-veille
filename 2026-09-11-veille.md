### 1. [Shopify : rapports inventaire → quantité on-hand dès le 1er sept.](https://changelog.shopify.com/posts/inventory-reports-now-show-on-hand-quantity)
- 📅 1 sept. 2026 (J-10) · 📺 Shopify Changelog officiel · 🏷 Shopify
- 💡 **TL;DR** : Les analytics Shopify mesurent désormais la quantité *on-hand* (tout ce qui est physiquement en stock, y compris unités réservées/indisponibles) et non plus la quantité *available* (seulement les unités vendables). Résultat : les chiffres semblent plus hauts qu'avant le 1er sept. et les comparaisons historiques sont incohérentes si tu traverses la date de coupure.
- ⭐ **Pourquoi Ivan** : Si TT ou PURESOLE utilisent les rapports ABC analysis, sell-through rate ou "days of inventory remaining", les ratios J-1/J+1 du 1er sept. sont faussés — toute décision de réappro ou de clearance basée sur ces rapports sans re-baseline est potentiellement incorrecte.
- 🎯 **Micro-action ≤15min** : Shopify Admin → Analytics → Inventory → ouvrir "ABC product analysis" + noter les valeurs actuelles dans Obsidian avec tag `#baseline-sept-2026`. Utiliser la date du 1er sept. comme point de rupture dans tout dashboard Shopify.

### 2. [Claude Inference Hooks beta — DLP en temps réel sur chaque prompt Enterprise](https://blog.checkpoint.com/ai-security/native-ai-security-comes-to-claude-why-anthropics-inference-hooks-matter/)
- 📅 Septembre 2026 · 📺 Anthropic (beta Enterprise) + Check Point · 🏷 Claude updates
- 💡 **TL;DR** : Inference Hooks = protocole webhook qui envoie chaque prompt + réponse Claude à un serveur de sécurité externe *avant* que Claude traite quoi que ce soit. Le serveur répond "allow" ou "deny" en temps réel. Compatible Zscaler, Palo Alto, Netskope, Proofpoint. Un refus affiche à l'utilisateur quelle politique l'a bloqué. Gratuit pour Enterprise, protocol publié open spec.
- ⭐ **Pourquoi Ivan** : Distinct des Enterprise Frontier Safeguards (data sovereignty) couverts le 9/9 — les Inference Hooks concernent le *contenu* des prompts. Si TT/PURESOLE scale vers un usage Claude Enterprise avec des données clients (adresses, historique commandes) dans les prompts, cette couche évite les fuites accidentelles sans changer l'infra.
- 🎯 **Micro-action ≤15min** : Lire l'article Check Point (lien ci-dessus, non bloqué) pour comprendre le schema du webhook → noter dans Obsidian les cas d'usage DLP pertinents pour PURESOLE (données clients dropship).
